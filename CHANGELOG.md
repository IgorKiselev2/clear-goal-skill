# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [SemVer](https://semver.org/lang/ru/).

## [0.2.2] — 2026-10-05

### Added
- **Строка версии в теле навыка.** Раньше версия была только во frontmatter,
  а его тело модели не показывается — агент не мог назвать свою версию.
- **HTTP-каталог OpenCode** (`catalog/`): `index.json` + `clear-goal-skill.md`.
  Пользователь один раз прописывает URL каталога в массив `skills`
  конфига, после чего обновления приезжают автоматически — OpenCode
  обновляет кэш при инкременте поля `version`. Требует OpenCode V2.
  Имя файла в каталоге именно `clear-goal-skill.md`, а не `SKILL.md`:
  в V2 корневой `SKILL.md` получает буквальный ID `SKILL`.
- **GitHub Action `sync-catalog`**: при изменении `SKILL.md` копирует его
  в каталог и поднимает `version` в `index.json`, чтобы клиенты увидели
  обновление. Защита от зацикливания — фильтр по путям и `[skip ci]`.
- **Секция «Обновление» в README** с тремя способами: каталог,
  одна команда вручную, git clone + junction. Плюс способ проверить
  установленную версию.

## [0.2.1] — 2026-10-04

Правки по результатам первого прогона навыка на живом запросе.

### Fixed
- **`description` переписан как триггер автозагрузки.** Было описание
  в третьем лице («превращает расплывчатый запрос…») — модель читала его,
  понимала идею и **имитировала** навык своими словами, не вызывая его.
  Стало указание в повелительном наклонении с явным моментом применения
  («ПЕРЕД началом работы»), запретом импровизировать свои уточняющие вопросы
  и перечнем механик, которые по памяти не воспроизвести.
- **Сквозная нумерация вариантов не соблюдалась.** На практике навык выдавал
  `1,2,3` в первом вопросе и снова `1,2,3` во втором, после чего предлагал
  ответить «1, 3» — неоднозначно. Добавлен строгий шаблон волны,
  контрпример и самопроверка перед отправкой.
- **Пометка `← по умолчанию` не проставлялась.** Требование усилено:
  ровно одна пометка в каждом вопросе, проверяется перед отправкой волны.
- **Шаг 2.5 не задавал выбор порядка.** Навык распознавал составную цель,
  отмечал это и шёл дальше. Теперь вывод выбора обязателен, задаётся
  отдельным сообщением до волны вопросов и не входит в лимит двух.

## [0.2.0] — 2026-10-04

Ревью качества навыка и устранение найденных дефектов. Изменения согласовывались
по одному; каждому соответствует отдельный коммит.

### Added
- **YAML-frontmatter** в `SKILL.md` по схеме OpenCode: `name`, `description`,
  `license`, `metadata`. Без него навык не попадал в список доступных и
  практически не подхватывался автоматически. `name: clear-goal-skill` совпадает
  с именем папки, как требует OpenCode.
- **Шаг 2.5 — расщепление составных целей.** Запрос вида «сделай X и Y»
  разбивается на отдельные цели со своим критерием Done у каждой, с выбором
  порядка. Исключение — части, бессмысленные по отдельности.
- **Шаг 4.1 — шкала риска.** Уточняющий вопрос задаётся только если цена
  неверной догадки средняя или выше; низкий риск закрывается значением
  по умолчанию.
- **Шаг 4.2 — волны вопросов.** Не более 2 вопросов за раз, между волнами
  GAP-анализ пересчитывается, потолок — 3 волны.
- **Шаг 4.3 — варианты ответа по цифрам.** К каждому вопросу 2–3 тезисных
  варианта со сквозной нумерацией плюс «свой вариант»; варианты берутся
  из разведки проекта, а не выдумываются.
- **Шаг 4.5 — обработка ответа «не знаю»** и маркер **`[от модели]`** у каждого
  значения, выбранного навыком самостоятельно. При высоком риске без дефолта
  навык не угадывает, а фиксирует неопределённость в разделе «Риски»
  и сужает цель до безопасной части.
- **Шаг 5.5 — gate самопроверки** из шести обязательных условий перед выдачей
  цели: исполняемая команда вместо описания состояния, наличие non-goal,
  одна цель в objective, лимиты, пометки предположений, существование
  команды проверки в проекте.
- **Пример 4 — анти-пример** с разбором, почему цель плохая, и исправленной
  версией.
- Явный блок **«НЕ применять»** с анти-триггерами.
- Правило **«сначала поиск по проекту, потом вопрос»**: ответы ищутся
  в `AGENTS.md`, `package.json`, `Makefile`, истории git.
- `CHANGELOG.md`, `.gitignore`, `temp/.gitkeep`.

### Changed
- **Условия применения навыка сужены.** Было «любая фраза о цели / хочу чтобы /
  сделай + описание работы» — под это подпадал почти каждый запрос к
  кодинг-агенту. Стало — признаки дефицита: нет объекта, нет критерия
  готовности, несколько идей в сообщении, длительный автономный прогон.
- **Детект goal-плагина** стал кроссплатформенным и однозначным: чтение файлом
  вместо `grep` (недоступного на Windows), проверка проектного и глобального
  конфигов в обоих расширениях, поиск `goal` только внутри секции `plugin`,
  кэширование результата на сессию.
- **Способ подключения плагина исправлен.** Было `npm i -g
  opencode-goal-plugin@latest` — неверно: OpenCode ставит плагины сам из
  конфига. Стало — запись с закреплённой версией в массив `plugin`
  файла `opencode.json`.
- Версии в таблице совместимости обновлены до фактических
  (`opencode-goal-plugin` 0.11.0, `@bybrawe/opencode-goal` 1.3.46, npm, 2026-10-04).
- Набор политик безопасности помечен как **пример** и сгруппирован
  по применимости (универсальные / Windows / Unix / БД) с условием применения;
  источником истины объявлен `AGENTS.md` проекта.
- Правило «проверь» ≠ «измени» перенесено из примера в критерий No-waste
  как универсальное.
- Примеры, демонстрировавшие антипаттерн склеенной цели
  (`--check "npm run build && npm run gen:wiki-llms"`), переписаны —
  в `SKILL.md` и в README.
- Термин приведён к единому «markdown-контракт» там, где речь о формате вывода.
- Список «Важных правил» переписан и перенумерован под новое поведение.

### Fixed
- **Противоречие «2 vs 3 вопроса»**: Шаг 4 требовал максимум 2, раздел правил —
  максимум 3. Приведено к единому поведению (волны по 2).
- **Непереведённый китайский фрагмент** `建议` в таблице Шага 5.
- **Ложное срабатывание детекта плагина**: поиск `goal` по всему конфигу
  срабатывал на строке команды `"Load clear-goal-skill…"` в секции `command`.
- Разнобой имён навыка (`goal-setting` против `clear-goal-skill`) в README
  и `PROJECT_SUMMARY.md`.
- Разнобой пометок предположений: было вперемешку `(предположение)` и
  `(предположение — проверьте)`, стало везде `[от модели]`.
