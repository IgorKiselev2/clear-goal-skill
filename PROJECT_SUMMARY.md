# PROJECT_SUMMARY.md

## Цель
Создать и опубликовать навык OpenCode для формулирования целей AI-агентов
с проверкой по SMART+STRONG, довести его до состояния, пригодного
для установки сторонними пользователями.

## Текущее состояние

**Версия 0.2.0** (2026-10-04), тег `v0.2.0`, репозиторий
`IgorKiselev2/clear-goal-skill`.

- Навык устанавливается в `~/.config/opencode/skills/clear-goal-skill/SKILL.md`
- `SKILL.md` содержит YAML-frontmatter по схеме OpenCode — без него навык
  не попадал в список доступных и автоматически почти не подхватывался
- Команды в конфиге: `/цель` (RU, развёрнуто), `/goalhelp` (кратко)
- Документация двуязычная: RU + EN-секция в `README.md`
- История изменений ведётся в `CHANGELOG.md`

## Этап 1 — создание v0.1.0 (2026-10-03)

Алгоритм постановки целей, 7 критериев SMART+STRONG, два формата вывода,
документация, MIT-лицензия, первый коммит.

### Что пробовали и что не сработало
1. **Копирование файлов через `Copy-Item`** — провал: кириллица в пути ломается.
   Решение: писать файлы напрямую через write-инструмент в целевую папку.
2. **Git SSH с кириллическим путём** — провал.
   Решение: короткий путь (`960A~1`) и переменная `GIT_SSH_COMMAND`.
3. **Host key verification** — провал из-за старого KEX-метода.
   Решение: `KexAlgorithms -sntrup761x25519-sha512@openssh.com` в ssh config.

### Находки
- Deploy key работает только при включённом **Allow write access**
- Git на Windows с SSH требует отдельного config для обхода KEX-ограничений
- Кириллица в путях PowerShell — только короткая нотация или запись напрямую

## Этап 2 — ревью качества и v0.2.0 (2026-10-04)

Внешнее ревью навыка с разбором по одному изменению: формат
«было → стало → почему» и выбор варианта. Принято 12 изменений, каждому
соответствует отдельный коммит. Полный список — в `CHANGELOG.md`.

### Ключевые дефекты, которые были найдены

| Дефект | Последствие | Как исправлено |
|---|---|---|
| Нет YAML-frontmatter | Навык практически не подхватывался автоматически | Frontmatter по схеме OpenCode, `name` = имя папки |
| Триггер «любая фраза о сделай» | Навык лез почти в каждый запрос | Условия по признакам дефицита + блок «НЕ применять» |
| «максимум 2» и «максимум 3» вопроса | Поведение непредсказуемо | Волны по 2, потолок 3 волны |
| Вопросы по всем пропускам | Допрос там, где цена ошибки нулевая | Фильтр по риску: спрашивать от среднего |
| `grep -i "goal"` для детекта плагина | Не работает на Windows, ложные срабатывания | Чтение файлом, поиск только в секции `plugin`, кэш на сессию |
| `npm i -g opencode-goal-plugin` | Неверный способ установки в принципе | Запись в массив `plugin` в `opencode.json` |
| Склеенный `--check "a && b"` | Частичный успех неотличим от провала | Шаг 2.5: расщепление составных целей |
| Нет проверки качества цели | Непроверяемые критерии вида «убедиться, что работает» | Шаг 5.5: gate из шести условий |
| Догадки неотличимы от фактов | Пользователь не видит, где решили за него | Маркер `[от модели]` |
| Личные политики зашиты в навык | Windows-правила применялись на macOS | Помечены как пример, сгруппированы по применимости |
| Фрагмент `建议` в тексте | Мусор в публичной репе, риск смены языка ответа | Удалён |

### Находки этапа
- Проверка npm-реестра окупилась: имена пакетов оказались **верными**,
  но способ установки — **неверным**. Документация плагина прямо говорит,
  что `npm install` не нужен.
- Поиск `goal` по всему конфигу давал ложное срабатывание на собственной же
  команде навыка (`"Load clear-goal-skill…"` в секции `command`).
- Примеры в документации сами демонстрировали антипаттерн склеенной цели —
  пришлось переписать и в `SKILL.md`, и в `README.md`.
- `.git/config` не сохраняется между сессиями в изолированном окружении,
  remote приходится прописывать заново — коммиты при этом не теряются.
